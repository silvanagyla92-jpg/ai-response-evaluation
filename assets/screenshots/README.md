# Screenshots

## 1. Objetivo

A pasta **screenshots** concentra evidências visuais selecionadas das atividades documentadas no projeto. As imagens têm função complementar: devem comprovar uma etapa, resultado, interface ou situação relevante e não apenas decorar a documentação.

## 2. O que pode ser registrado

Uma captura pode demonstrar, por exemplo:

- execução de uma atividade;
- resultado de uma avaliação;
- configuração utilizada;
- interface de uma plataforma;
- comparação de respostas;
- evidência de conclusão de um exercício;
- organização de um ambiente de prática.

## 3. Critérios para uma boa evidência

A imagem deve ser legível, contextualizada e relacionada a uma informação descrita no documento correspondente. Sempre que necessário, a legenda deve explicar o que a imagem comprova.

## 4. Privacidade e segurança

Antes de publicar uma captura, devem ser removidos ou ocultados dados pessoais, credenciais, tokens, e-mails, identificadores privados, informações de clientes e qualquer conteúdo confidencial.

Não devem ser publicados materiais internos ou protegidos de plataformas quando sua redistribuição não for autorizada.

## 5. Organização

As imagens devem permanecer dentro de `assets/screenshots/` e ser referenciadas pelos documentos que dependem delas. Evite duplicar arquivos desnecessariamente.

```text
assets/
└── screenshots/
    ├── README.md
    └── evidências visuais
```

## 6. Relação com QA e Auditoria

Evidências visuais aumentam a rastreabilidade de uma atividade quando preservam contexto suficiente para revisão. Entretanto, uma captura de tela isolada não substitui a descrição textual do procedimento e da decisão.
